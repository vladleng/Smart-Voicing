# Версионирование Smart Voicing

Для проекта используется простая схема рабочих и завершённых версий.

## Принцип

- Буквенные суффиксы (`a`, `b`, `c`...) используются для промежуточных рабочих сборок внутри этапа разработки.
- После успешного завершения этапа версия повышается до следующего числового значения.
- Имя продукта и идентификаторы плагина остаются стабильными (`Smart Voicing`), а номер версии используется в имени тестовой/распространяемой сборки и в документации.

## Текущая последовательность

- `Smart Voicing 0.0a` — базовый VST3-каркас, первая рабочая сборка. Этап 0.
- `Smart Voicing 0.0b` — рабочая сборка этапа ARA Context Proof of Concept. Этап 1.
- `Smart Voicing 0.1` — готовая версия после успешного завершения этапа ARA Context Proof of Concept.

## Далее

После `0.1` следующий этап начинается с промежуточной версии вида:

- `0.1a`
- при необходимости `0.1b`, `0.1c` и т. д.
- после завершения этапа — `0.2`

Далее схема повторяется аналогично:

`0.2a` → `0.2b` → ... → `0.3`

## Важное правило

Не менять `PRODUCT_NAME`, VST3 UID/manufacturer code или bundle id ради номера версии. Это нужно, чтобы DAW воспринимала обновления как один и тот же плагин, а не как новый продукт.

Версия должна отражаться в:

- имени сборочного артефакта;
- debug UI;
- Release/PR/Issue;
- документации проекта.
